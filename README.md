# FPC-8612 + FireBeetle 2 ESP32-E: photo test

Минимальный тест вывода фотографии на чёрно-белую панель 7.5″, 800×480,
с маркировкой шлейфа `FPC-8612` через адаптер `DESPI-C02`.

## Подключение

| DESPI-C02 | FireBeetle 2 ESP32-E | GPIO |
|---|---|---:|
| 3.3V | 3V3 | — |
| GND | GND | — |
| SDI | MOSI | 23 |
| SCK | SCK | 18 |
| CS | D7 | 13 |
| D/C | SCL | 22 |
| RES | SDA | 21 |
| BUSY | D6 | 14 |

Важно:

- подавайте на `DESPI-C02` только `3.3V`, не `VCC/5V`;
- переключатель `RESE` установите в положение `0.47Ω`;
- соединяйте всё при отключённом USB-питании;
- контакт 1 шлейфа экрана должен попасть на контакт 1 разъёма адаптера;
- при прямой установке экран и сторона DESPI-C02 с компонентами должны смотреть вверх;
- первое полное обновление экрана может занять 20–30 секунд.

## Сборка и прошивка (PlatformIO)

1. Откройте эту папку в VS Code с расширением PlatformIO.
2. Подключите FireBeetle кабелем USB-C с передачей данных.
3. Выполните `PlatformIO: Upload`.
4. При необходимости откройте Serial Monitor со скоростью 115200 бод.

На дисплей однократно выводится подготовленная чёрно-белая фотография размером
800×480. После обновления контроллер дисплея переводится в сон, а изображение
остаётся на экране.

## Энергосберегающий цикл

После каждого обращения к серверу FireBeetle отключает Wi-Fi и переходит в
Deep Sleep с пробуждением по RTC-таймеру. При успешном запросе длительность сна
приходит вместе с PNG в заголовке `X-Next-Refresh-Seconds`; при ошибке плата
повторяет попытку через 30 секунд.

С 23:00 до 06:00 по часовому поясу панели сервер назначает интервал не менее
одного часа. В остальное время используется интервал, выбранный в панели
управления.

ETag последнего успешно показанного изображения и его локальный хеш хранятся в
RTC-памяти ESP32. Если погодный срез не изменился, сервер отвечает `304 Not
Modified`, PNG не передаётся, а полный цикл обновления E-Ink не запускается.
После полного отключения питания RTC-память очищается, поэтому первое
пробуждение всегда загружает и выводит изображение заново.

Прошивка выполняет только один HTTPS-запрос — к `DEVICE_BASE_URL/screen.png`.
Отдельный запрос `/config` для каждого пробуждения больше не требуется.

Исходное фото преобразуется скриптом `tools/convert_photo.py`: пропорции
сохраняются, изображение центрируется на белом фоне, а полутона передаются
чёрно-белым дизерингом.

В данной связке сигнал `BUSY` освобождается раньше физического завершения
обновления. Драйвер поэтому дополнительно ждёт 25 секунд перед отключением
питания панели.

## Почему в проекте отдельный драйвер

`FPC-8612` также встречается как `DEPG0750RWF86BF30`. Его последовательность
инициализации отличается от обычной `GxEPD2_750c_Z08`, поэтому проект включает
адаптированный драйвер `GxEPD2_750c_86BF`.

Драйвер взят из открытого MIT-проекта
[`lumixen/gxepd2-rwf86bf`](https://github.com/lumixen/gxepd2-rwf86bf);
текст лицензии сохранён в `LICENSE`.
